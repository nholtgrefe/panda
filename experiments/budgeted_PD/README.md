# Supplementary data and scripts (budgeted PD paper)

This folder contains the datasets and scripts supporting the experiments in the paper:
> **Tractable Optimization of Budgeted Phylogenetic Diversity on Networks Utilizing Node-Scanwidth**.
> *Niels Holtgrefe and Jannik Schestag*.

The results in this paper (and in this folder) were obtained using version `2.1.2` of `phypanda`, except for the comparison with PaNDA (scripts `06` and `07`), which uses version `1.0.3`. To install these versions, run `pip install phypanda==2.1.2` or `pip install phypanda==1.0.3`, preferably in separate environments.

Version `2.1.2` fixes a bug in earlier `2.x` versions, in which edges of branch length 0 were treated as edges of length 1 by the optimization algorithms. All results in this folder were computed with the fixed version.

All computations were performed on a laptop with Debian 12 on a single core of an Intel® Core™ i5-1245U Processor.

## Datasets

- **Simulated networks** (`simulated_networks.csv`): The non-binary networks used for the experiments were obtained from the binary networks of the PaNDA paper (`../MAPPD/exp1_simulated_networks.csv`). For each network, the 10% shortest edges were contracted, while preserving adherence to our network definition and the level of the network: an edge was only contracted if this did not merge two blobs (maximal connected subgraphs without cut-edges). This procedure was performed with the script `01_generate_networks.py` (using `phylozoo` version `0.1.2`). The file contains 6400 networks with columns: `id` (5-digit network identifier, corresponding to the original network ids), `ntips` (number of leaves, 20, 50, 100 or 200), `level` (level of the network, from 0 to 15), and `newick` (the network as eNewick string). There are 100 networks for each combination of number of leaves and level.

- **Taxon costs** (`simulated_costs.csv`): The taxon costs were sampled from a log-normal distribution using the script `02_generate_costs.py`. Each row contains `id` (network identifier) followed by a list of taxon–cost pairs in the format `(taxon,cost)`.

- **Empirical networks** (`empirical_networks.csv`): The 27 real phylogenetic networks used in the experiments of the scanwidth paper (Holtgrefe, van Iersel and Jones, JCSS 2026; originally from http://phylnet.univ-mlv.fr/), taken from the folder `experiments/networks/real_networks` of the [scanwidth repository](https://github.com/nholtgrefe/scanwidth). Each row contains `name` and `arcs` (a comma-separated list of `(tail,head)` arcs). The networks are stored as arcs rather than eNewick strings, because several of them contain vertices with indegree and outdegree 1, and are therefore not phylogenetic networks in the sense of PhyloZoo.

## Experiments

- **Node-scanwidth extensions** (`simulated_nsw_extensions.csv`): The optimal node-scanwidth extensions were computed with the script `03_compute_simulated_nsw.py` and saved with columns: `id` (network identifier), `nsw` (node-scanwidth), `comp_time_xp` (computation time in seconds), and `extension` (a comma-separated ordering of the nodes forming the extension). An extension is an alternative representation of a tree-extension.

- **Algorithm benchmark** (`simulated_results.csv`): The benchmark runs were performed with the script `04_run_simulated_experiments.py`. Each row records the timings and diversity values for a single network, for three diversity measures (all-paths, max-tree, min-tree) and three budgets (25%, 50% and 90% of the total taxon cost). Columns: `id`, `level`, `tot_cost` (total taxon cost), `time_net` (network parsing), `time_ext` (building the tree-extension), and for each measure and budget `time_<measure>_<budget>` (solve time in seconds) and `val_<measure>_<budget>` (diversity value), with `<measure>` in `ap` (all-paths) and `mxt` (max-tree) and `<budget>` in `b25`, `b50`, `b90`. The min-tree measure is computed for the full taxon set, in `time_mnt_full` and `val_mnt_full`. In addition, all-paths diversity is maximized with unit taxon costs (every taxon costs 1) and budgets of 25%, 50% and 90% of the number of leaves, in the columns `time_apu_<budget>` and `val_apu_<budget>`; these are the instances used in the comparison with PaNDA. An initial warm-up run was performed on a single network to compile the code with numba/JIT; this run was not counted in the reported computation times.

- **Large networks** (`large_results.csv`): The experiments on the 20 large networks with 1000 taxa, each obtained by identifying the roots of five randomly selected 200-taxon networks, were performed with the script `05_run_large_experiments.py`. The results (including the networks and their taxon costs) were saved in this file.

- **Comparison with PaNDA**: The node-scanwidth algorithm was compared with the edge-scanwidth algorithm of PaNDA (phypanda `1.0.3`) on unit-cost instances. Both scripts must be run with phypanda `1.0.3`.
  - `06_compute_simulated_esw.py` samples 25 networks for each combination of number of leaves and level (1600 networks, seed 42) from `simulated_networks.csv`. Since PaNDA requires binary networks, it computes a binary resolution of each network, followed by an optimal edge-scanwidth extension of the resolution with the algorithm of phypanda `1.0.3`. The binary resolution of phypanda `1.0.3` (`DirectedNetwork.binary_resolution`) contains a bug that makes it fail on vertices with indegree larger than 2, which occur in 513 of the 6400 networks. We therefore used a fixed version of the same construction, included in the script, in which the new vertices also get deterministic names. (From version `2.0.0`, phypanda uses the binary resolution of PhyloZoo, which does not have this bug.) The results are saved in `simulated_esw_extensions.csv` with columns: `id`, `esw` (edge-scanwidth of the binary resolution), `time_net` (network parsing), `time_res` (binary resolution), `comp_time_xp` (computation of the edge-scanwidth extension), `resolution` (the binary resolution as a list of `(tail,head,length)` arcs) and `extension` (a comma-separated ordering of the nodes of the resolution). The resolutions are stored as arcs, because the eNewick format written by phypanda `1.0.3` cannot be read by PhyloZoo.
  - `07_run_esw_experiments.py` solves the unit-cost instances (budgets of 25%, 50% and 90% of the number of leaves) on each binary resolution with PaNDA (`solve_MAPPD`), using the saved extension. The results are saved in `simulated_esw_results.csv` with columns: `id`, `level`, `ntips`, `esw`, `time_net` (building the resolution from its arcs), `time_ext` (building the tree-extension), and `time_panda_<budget>` and `val_panda_<budget>` for each budget. For all 1600 networks and budgets, the values equal the columns `val_apu_<budget>` of `simulated_results.csv`.

- **Node-scanwidth of the empirical networks** (`empirical_nsw_extensions.csv`): The optimal node-scanwidth of the empirical networks was computed with the script `08_compute_empirical_nsw.py`, with the same settings as `03_compute_simulated_nsw.py`, and saved with columns: `name`, `nsw`, `comp_time_xp` and `extension`.
